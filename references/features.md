# 功能清单

本文件列出孟总会务助手当前具备的所有功能，方便你增加、删除、修改。

> **修改约定**：每个功能用 `## X.Y 功能名` 组织。删除功能直接删除对应章节；新增功能按编号顺序追加；调整功能改对应章节内容。

---

## 1. 会议录入

### 1.1 文字排会

用户用自然语言或结构化文字描述会议，agent 解析后写入行程表。

**触发词**：帮我安排会议 / 把这个会议加进行程表 / 排会

**输入示例**：
- "今天 11:20-12:00 跟邓在 302 开会，讨论三季度战略"
- "周三下午两点开组织生活会，议程：1.学习 2.讨论 3.总结"

**输出流程**：读取结构 → 识别字段 → 给预览 → 用户确认 → 写入 → 回读校验

### 1.2 截图排会

用户发送企业微信截图、会议通知截图，agent 识别后写入。

**触发词**：截图排会 / 这个会议加进去（带图片）

**支持来源**：企业微信、微信、邮件、任意可读图片

**识别字段**：会议标题、时间、地点、参会领导、参会人员、议程

### 1.3 多会议批量排

一次输入多个会议（如一段话里说了 3 场），agent 自动拆分并分别写入。

**触发词**：今天有这些会议 / 这周安排

### 2.2 检测时间冲突

**触发词**：检查冲突 / 有没有撞会

## 3. 版面整理

### 3.1 应用底色

按"排会规则 A.1"给指定行填底色。

**触发词**：填底色 / 调色 / 标色

### 3.2 应用对齐

按"排会规则 A.2"给指定列设对齐方式。

**触发词**：调整对齐 / 左对齐 / 居中

### 3.3 应用换行

按"排会规则 A.3"给指定列设自动换行。

**触发词**：自动换行 / 换行

### 3.4 隐藏空白行

按"排会规则 B.8"把指定天的空白行隐藏。

**触发词**：整理版面 / 隐藏空白行 / 把周五整理一下

### 3.5 展开所有行

把指定天/全表所有隐藏的行展开（恢复可见）。

**触发词**：展开 / 显示所有行 / 取消隐藏

### 3.6 还原误改行高

恢复被 `setRowHeightsForced` 误改的行高（最高到 45pt）。

**触发词**：恢复行高 / 还原 R56

## 4. 表格结构识别

### 4.1 自动识别每周标记行

根据 B 列内容（"周一"/"周二"/...）自动识别每天的起始行。

### 4.2 自动识别午休分隔行

根据行高（9~20pt）自动识别午休分隔行。

### 4.3 自动识别当天行范围

基于标记行 + 午休分隔行 + 下一个标记行，自动算出当天的所有行号范围。

### 4.4 自动识别哪几行有会议

根据 C 列时间字段非空判断，区分"会议行"和"空白行"。

## 6. 工具脚本

### 6.1 `scripts/cdp.py`

CDP 客户端，通过 websocket-client 接管用户 Chrome 浏览器。

**能力**：
- `CDP.send(method, params)` 调任意 CDP 命令
- `CDP.eval(expression)` 在页面执行 JS
- `get_page_ws(port)` 获取目标页面的 ws URL

### 6.2 `scripts/sheet_ui.py`

sheet UI 操作封装，常用坐标、点击、按键函数。

**能力**：
- `click(x, y)`：真实鼠标点击
- `key(key)`：模拟键盘按键
- `snapshot(path)`：截图
- 名称框跳转、整行选中、右键菜单等场景封装

### 6.3 `scripts/publish_to_baidu.py`

自动发布脚本（每天 23:59 自动跑，或用户手动触发）。

**流程**：检测变化 → 打包 → 部署 EdgeOne → 转存百度网盘 → 写 CHANGELOG

**当前限制**：因 WorkBuddy 沙箱代理挡 GitHub HTTPS（实际未跑通），**当前流程只完成到打包**，跨设备同步靠 Git（5.3）。

### 6.4 `scripts/decode_to_zip.py`（计划中）

base64 → zip 还原脚本。**当前未实现**——因为有 Git 方案后不再需要 base64 兜底。

### 7.7 发版完成汇报 + 技能大小预警

发版完成后，agent 自动向用户汇报**技能大小**和**效率预警**。

**触发词**：
- 用户手动问："技能多大 / 技能大小 / 文件多大 / 现在技能多少 KB"
- 发版完成后 agent 自动汇报（无需触发词）

**汇报内容**：
- 当前版本号
- 技能目录总大小（KB）+ 文件数
- 分组大小（references/、scripts/、根目录）
- SKILL.md 单独大小（LLM 加载的关键文件）
- 当前所在阈值区间 + 剩余多少 KB 到达下一档

**效率预警阈值**（基于 LLM 加载 + 文件上传实务）：

| 等级 | 总大小 | SKILL.md | 影响 | 建议 |
|---|---|---|---|---|
| 🟢 健康 | < 50 KB | < 16 KB | 几乎无影响 | — |
| 🟢 良好 | 50~100 KB | 16~30 KB | 正常（当前区段） | 继续 |
| 🟡 警戒 | 100~200 KB | 30~60 KB | LLM 加载变慢 | 拆 references/ 大文档 |
| 🟠 警告 | 200~500 KB | 60~100 KB | 拖慢首屏响应 | 拆分 SKILL.md 章节到独立文件 |
| 🔴 危险 | > 500 KB | > 100 KB | 严重卡顿 | 必须重构 |

**实现**：
- `scripts/publish_to_baidu.py --size` 查看当前大小 + 评估（不发版）
- 发版流程结尾自动调 `compute_size()` 并打印汇报

### 7.8 文档分层与体积纪律

**触发**：每次新增/修改技能文档时自动遵守；用户问"技能多大"时一并汇报。

**分层原则**（2026-09-14 立，起因：SKILL.md 涨到 41 KB）：

| 层 | 文件 | 定位 | 加载时机 |
|---|---|---|---|
| 入口 | `SKILL.md` | 红线 + 开工闸门 + 触发词 + 通道结论 + 工作流骨架 + 文档地图 | **每次触发都读**，**目标 ≤ 15 KB** |
| 规则 | `references/rules.md` | 排会规则权威来源（A~E 五类） | 动手前按需读相关章节 |
| 手册 | `references/cdp_notes.md` | 通道 B 操作手册（sandbox/CDP/键盘/脚本/踩坑） | CDP 相关操作前 |
| 发版 | `references/publishing.md` | 版本号约定、发版 6 步、git 踩坑、体积纪律 | 发版时 |
| 清单 | `references/features.md` | 功能清单权威来源 | 说"展示功能"时 |
| 日志 | `references/CHANGELOG.md` | 已发布 + 待发布草稿 | 说"展示更新日志"时 |

**纪律**：
1. **禁止重复**——同一内容只允许一个权威位置，别处只放指针
2. 新增内容前先问"别处是不是已经写过？"是就只加指针
3. 每次发版汇报时看 SKILL.md 单项：**超 30 KB 就必须拆**
4. references 文件名要能自解释；新文件必须在 `SKILL.md` 的文档地图里登记

**实测记录**：2026-09-14 瘦身前 SKILL.md 41.01 KB（🟡）、总 173.5 KB；
拆出 `cdp_notes.md` + `publishing.md` 后 SKILL.md **15.7 KB（🟢 健康，降 62%）**、总约 170 KB。

## 8. 周期维护

> 涉及周频的清理 / 同步动作。**注意：所有破坏性操作（清空/删除）执行前必须先列出受影响行，等用户确认再动手。**

### 8.1 周日自动清理上周数据 + 展开隐藏行

每到周日开始排新一周周一的会时，自动：
1. 删除上周（本周一到本周五）的所有会议信息
2. 展开上周（本周一到本周五）的所有隐藏行

**触发时机**：
- **自动**：周日开始排下周一的会时
- **手动**："清理本周 / 跑一次清理 / 模拟周日清理 / 执行 8.1"

**清理范围定义**：
- "上周 = 本周一 ~ 本周五"（因为周一~周五才是工作日，会议只在工作日）
- 表格中的行范围 ≈ R3~R69（周一标记行 ~ 周六标记行之前一行）
- **B 列标记行（B="周一/周二/.../周五"）保留**（结构性数据）
- **午休分隔行（行高 9~20）保留**（结构性数据）

**清理字段**：
- C（时间） / D（会议名称） / E（议程） / F（地点） / G（参会领导） / H（参会人员） / I（组织人）
- 不清空底色 / 对齐 / 换行（这些是用户预设，下次新数据来了再覆盖）

**展开隐藏行**：
- 范围：周一~周五标记行之间的所有行
- 取消所有隐藏状态（恢复可见）

**安全约束**：
- **必须先用 sandbox 读出本周有会议的行 + 截图确认隐藏行 → 列清单 → 用户确认 → 才执行**
- 不可一键无脑执行

**实施步骤**（用户手动触发"清理本周"时）：
1. 用 sandbox 读 R3~R69 的 B~I + 行高，识别有会议的行（C 列非空）
2. 用 CDP 截图周一周五的当前状态，识别被隐藏的行（截图对照行号是否跳号）
3. agent 输出"即将清空 + 即将展开"的清单给用户
4. **用户确认后**才执行：
   - 用 sandbox 把有会议行的 C:I 清空
   - 用 CDP `Alt+Shift+9` 取消隐藏行
5. 截图验证：会议行 C:I 已空 + 隐藏行全部展开
6. 回读 sandbox 校验：所有 R3~R69 的 C:I 都是空

**自动化计划**（待用户确认行为正确后再启用）：
- 在排会流程开头增加判断：今天是周日 且 本周一的会还没排 → 触发自动清理
- 或者：用 automation 每周日 22:00 提醒用户"要不要清理本周数据"
- 暂不直接自动执行清理（破坏性操作需用户最后确认）

**实现**：
- 文档化（不写脚本，靠 agent 调 sandbox + CDP）
- 后续可沉淀到 `scripts/weekly_reset.py`
